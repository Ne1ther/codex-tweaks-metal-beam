# 性能与训练吞吐：测到了什么

以下为 0.3.6 的历史记录；0.3.7 已移除账号区域雾光，未重新运行训练基准。这里记录的是已完成的有限测试，不把单个 GPU 占用截图当作训练影响，也不保证所有设备和 Codex 窗口都能保持某个占用百分比。

## 满载训练对照

测量日期：2026 年 9 月 25 日。设备为 Apple M3 Max、64 GiB 统一内存。PyTorch 2.11 使用 MPS 后端，关闭算子 CPU fallback；约 337 万参数的 GNN / DeepONet 模型、batch 32，模型与输入常驻 GPU。每步实际包含前向、MSE、反向、梯度裁剪及 AdamW 更新。

每轮恢复相同初始权重、随机状态和优化器，先运行 8 个不计时的预热步，然后测量约 6 秒。每 8 个训练步同步一次，按实际完成步数和经过时间计算吞吐。共六组配对、十二个有效窗口，累计 1,560 个计时训练步。

插件部分使用 **0.3.6 实际渲染代码的固定预览布局**，在 Codex 内置浏览器中运行，视口为 737 × 1017 CSS 像素、DPR 2。布局含两个金属表面、一个被动反光、一个输入框流光，以及账号、模型、模式文字效果。测试时临时关闭宿主里的另一份效果，避免叠加。所有开启窗口均确认动画帧数增长、页面可见并持有焦点。

| 测量项 | 关闭特效 | 开启特效 |
| --- | ---: | ---: |
| 有效窗口 | 6 | 6 |
| 实际计时总秒数 | 37.438 | 36.895 |
| 完成的计时训练步 | 792 | 768 |
| 训练步 / 秒 | 21.1549 | 20.8160 |
| 样本 / 秒 | 676.958 | 666.112 |
| 驱动报告 GPU 忙碌率 | 99%–100% | 99% |
| 动画呈现帧率 | 不适用 | 约 50 fps |

将各组完成步数相加，再除以各自实际计时时间，得到整体吞吐。开启效果后吞吐下降 **1.60%**，完成相同工作所需时间增加 **1.63%**。六组各自的吞吐下降为 **1.30%–1.81%**。

GPU 已接近满载时，忙碌率本身不会显示工作分配如何变化；因此这里比较实际训练吞吐。上述 1.60% 是吞吐变化，**不是插件的 GPU 占用百分比**。

## 热状态与功率的限制

先前的持续满载探索出现明显的系统热限制和训练吞吐持续下降，关闭插件时也发生，不能据此归因给插件。因此有效对照使用轮间冷却和短计时窗口，交替开关顺序。

有效窗口均未观察到所采集的 CLTM 限制标志，GPU 忙碌率至少 99%。起始温度大约 59–66°C，各配对的起始温差在 0.02–2.73°C 之间。探索时原先的冷却阈值难以再次达到，后续阈值调整为 66°C；仍保留轮间至少 15 秒冷却及测量窗口内的忙碌率、温度和限制标志筛选。这是探索性对照，不是预注册基准。

系统 IOReport 能量计数估算的整颗 GPU 功率均值约为 **36.2 W（关闭）与 41.0 W（开启）**。短窗口波动和计数估算误差使其不能作为插件单独功耗的精确测量，更不能推断为固定增加 4.9 W。

这项测试支持“该固定布局在本机短时满载时的训练速度损失较小”，不支持以下推断：完整 Codex 界面同样只有 1.6% 开销、长期训练一定只慢 1.6%、所有设备 GPU 占用低于 5%，或训练精度不受任何其他因素影响。没有测量最终模型精度；吞吐测试重复使用训练输入，不是一次完整科研训练。

测试结束后已停止训练 / 遥测进程、关闭预览并删除原始临时脚本、日志和结果，恢复宿主插件原先的启用状态。仓库仅保留这份汇总，不分发训练数据、权重或原始测试记录。复现需要重新准备自己的训练负载。

## 渲染设计

- 金属高频绘制只覆盖细窄的边缘网格，避免每帧处理空白中心。
- 反射和柔光共用低频源，空闲约 6 fps、运行约 12 fps；亮度读回最多每 1.5 秒一次。
- 静态纹理与位移 / 透明度动画减少高频绘制，但仍有合成成本。
- 控件几何变化时再更新反射位置，悬停不额外创建材质实例。
- 页面隐藏、窗口失焦、减少动态效果时暂停；控件离屏及插件停用时回收相应资源。

早先的渲染调用计数和预览检查见 [VALIDATION.md](../VALIDATION.md)。这些记录与本次满载训练测量是不同实验。
